# 大纲解析目标字数网页显示修复

## 摘要

用户反馈：命令行验证大纲解析后目标字数已分配，但网页上点击解析后，“目标字数”输入框仍显示 0。

原因不是解析逻辑未生效，而是 Streamlit 的 `number_input` 使用了固定 key。解析后虽然 `ProjectKnowledgeBase` 中的 `sec.word_count` 已更新，但同名 widget key 会继续复用旧的前端状态值 `0`，导致页面显示仍为 0。

## 修改文件

- `libriscribe/src/libriscribe/web/app.py`
  - 在章节列表渲染前读取 `outline_parse_version`。
  - 将小节标题、写作目标、目标字数三个输入控件的 key 加入 `outline_parse_version`。
  - 每次大纲重新解析后，已有逻辑会递增 `outline_parse_version`，从而强制 Streamlit 重建小节编辑控件，避免继续显示旧的 0。

## 验证

已运行：

```bash
python -m pytest tests/test_commercial_routes.py -q
```

结果：`66 passed in 3.17s`。

## 备注

如果浏览器仍显示旧值，需要刷新页面或重新点击“解析大纲 / 用当前大纲重建章节”。本次修改后重新解析会自动换 key，不再沿用旧输入框缓存。
