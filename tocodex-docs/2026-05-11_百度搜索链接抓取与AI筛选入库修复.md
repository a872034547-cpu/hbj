# 百度/API 链接抓取与 AI 筛选入库修复

## 摘要

修复资料助手第四步百度/搜索 API 兜底逻辑：搜索 API 返回的标题和 URL 不再直接作为资料证据入库。系统现在会先打开返回链接、抽取网页正文，再把网页内容交给 AI 进行相关性、可信度和章节支撑筛选；只有 AI 明确保留的网页资料才会写入资料来源库。

## 修改文件

- `libriscribe/src/libriscribe/services/literature_search_service.py`
  - 新增 `fetch_web_page_text()`：支持打开百度跳转链接/普通网页链接、跟随重定向、识别 HTTP/Content-Type 错误并返回诊断。
  - 新增 `extract_readable_text()`：用标准库清理 HTML，移除脚本、样式和标签，抽取可交给 AI 判断的网页正文。

- `libriscribe/src/libriscribe/web/app.py`
  - 移除“搜索标题+URL 直接入库”的逻辑。
  - 新增 `_screen_web_page_with_ai()`：将已抓取网页正文交给 AI 判断是否可入库。
  - 新增 `_sources_ai_screening_keep()`：解析 AI 的“保留：是/否”结论。
  - 新增 `_import_screened_web_pages_as_sources()`：只保存 AI 筛选通过的网页资料，资料类型为 `web_page_ai_screened`。
  - 改造 `_run_sources_ai_gap_search()`：流程变为 `搜索候选 → 打开网页 → AI筛选 → 通过后入库`，并返回 API 失败、网页打不开、AI 剔除等诊断信息。
  - 页面调用百度/API 兜底时会把当前 `client` 传入筛选流程。

- `libriscribe/tests/test_commercial_routes.py`
  - 更新百度/API 兜底测试，验证必须先打开网页并经过 AI 筛选后才能入库。
  - 新增 API 400/AI 剔除场景测试，确保失败或无关网页不会把标题/URL 当证据保存。
