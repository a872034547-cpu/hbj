# 大纲管理旧项目目标字数兜底修复

## 摘要

用户反馈网页仍显示 `目标字数 0`。进一步判断：不仅是 Streamlit 控件缓存问题，还存在旧项目/旧会话已经保存了 `word_count=0` 的章节数据，导致即使刷新控件，页面仍按旧数据展示 0。

本次增加网页渲染前的兜底补齐逻辑：只要章节中存在父级小节有目标字数、下级小节目标字数为 0，就在“大纲管理”渲染前自动按层级分配并保存项目。

## 修改文件

- `libriscribe/src/libriscribe/web/app.py`
  - 在章节列表渲染前新增 `_fill_missing_section_words_for_display()`。
  - 对旧项目/旧会话中已保存为 0 的小节字数进行自上而下补齐。
  - 补齐后自动更新 `project_data`、递增 `outline_parse_version` 并保存项目，确保输入框 key 和底层数据同时更新。
