# 四个 Bug 修复与叶子节点生成逻辑

## 摘要

修复了用户报告的三个 bug 和一个运行时发现的 AttributeError，并实现了"有子节的小节只生成叶子节点内容"的新需求。

## 修改文件

1. **`libriscribe/src/libriscribe/web/app.py`**
   - Bug 1: `_render_task_results()` 中的 `clear_completed_tasks` button key 重复 — 在 `render_editor_page()` 中移除重复调用，由 `main()` 统一处理
   - Bug 2: 创建项目表单 LLM 提供商增加 `format_func` 显示友好名称，选择"自定义第三方"时显示 API Base/Key/Model 输入框；`create_new_project()` 增加 `custom_api_base`/`custom_api_key`/`custom_model` 参数
   - Bug 3: `BackgroundTaskManager._run()` 检查返回值是否以 `ERROR:` 开头，若是则将状态标记为 `failed` 而非 `completed`
   - Bug 4: 编辑器页面 `sec.summary` 改为 `getattr(sec, 'summary', '')` 安全访问
   - 新需求: 编辑器页面小节列表中，非叶子节点（有子节）不显示"生成此小节"按钮，改为提示"请选择子小节生成"

2. **`libriscribe/src/libriscribe/agents/chapter_writer.py`**
   - `_write_academic_chapter()`: 增加叶子节点过滤逻辑，有子节的小节只输出标题，不调用 LLM 生成内容；`ordered_sections` 改为只包含叶子节点（用于 LLM 调用），`all_sections` 保留用于构建大纲树和输出标题层级

## 修复详情

### Bug 1: clear_completed_tasks key 重复
- **原因**: `_render_task_results()` 在 `main()` (全局) 和 `render_editor_page()` (编辑器页面) 都被调用，导致 Streamlit button key 冲突
- **修复**: 编辑器页面不再调用 `_render_task_results()`，由 `main()` 统一渲染任务结果

### Bug 2: 创建项目时 LLM 提供商缺少自定义选项
- **原因**: 创建项目表单的 LLM selectbox 没有 `format_func`，也没有在选择 custom 时展示自定义 API 字段
- **修复**: 增加 `format_func` 显示友好名称；选择 custom 时显示 API Base/Key/Model 输入框；`create_new_project()` 接收并保存自定义配置

### Bug 3: AI 调用失败标记为 completed
- **原因**: `_bg_write_chapter` 等后台函数返回 `"ERROR: ..."` 字符串而非抛异常，`BackgroundTaskManager._run()` 将所有正常返回的任务标记为 completed
- **修复**: 在 `_run()` 中检查返回值，若以 `"ERROR"` 开头则标记为 `failed`

### Bug 4: ChapterSection.summary AttributeError
- **原因**: 旧项目 JSON 中的 ChapterSection 可能缺少 `summary` 字段，Pydantic v2 的 `__getattr__` 会抛 AttributeError
- **修复**: 使用 `getattr(sec, 'summary', '')` 安全访问

### 新需求: 有子节的小节只生成叶子节点
- **需求**: 如 1.1 下有 1.1.1、1.1.2，则 1.1 不单独生成内容，只生成 1.1.1 和 1.1.2
- **实现**: 
  - `chapter_writer.py` 中判断 section_number 是否为其他 section 的前缀，若是则为非叶子节点，只输出标题
  - UI 中非叶子节点不显示"生成此小节"按钮
