# 好编辑 / Libriscribe 2.0 同类产品深度分析与升级路线图

创建时间：2026-05-10  
范围：AI 学术写作、知识库写作、专著生成、引用核验、商业化自动运营

## 一、结论摘要

当前 Libriscribe / 好编辑已经具备“项目创建—AI 大纲—小节写作—章节审校—导出”的基本闭环，并且已完成多项关键修复：自定义 OpenAI 兼容模型、全书大纲分章生成、实时章节写作、标题清洗、普通章/末章结构区分、反幻觉引用约束、PDF/DOCX 导出等。

但从 Jenni、Paperpal、NotebookLM、Jasper、Copy.ai、QuillBot 等同类产品能力看，现阶段仍更像“本地 Streamlit 写作工具”，距离“商业可自动运营的学术专著生产平台”还有明显差距。2.0 的核心不应只是继续堆按钮，而要围绕三条主线重构：

1. **可信资料链**：从“上传资料后检索”升级为“来源库—证据片段—引用记录—正文声明—导出参考文献”的可追溯闭环。
2. **专著生产流水线**：从“点击生成章节”升级为“规划、研究、写作、核验、审校、导出”的可恢复、多阶段、可观测任务系统。
3. **提示词与风格治理**：从“单个长提示词”升级为“全书宪法、章节策略、小节执行、引用核验、审校评分、改写润色”的分层提示词体系。

2.0 第一阶段建议优先做“可信资料与引用核验 + 专著流水线面板 + 提示词中心”，这三项最能直接解决用户关心的商用可靠性、引用幻觉、章节质量不一致和操作混乱问题。

## 二、同类产品能力拆解

### 1. Jenni AI：学术写作与引用一体化

核心定位：面向论文和学术写作的“read, write, cite”工作台。

可借鉴能力：

- 文献搜索与导入：支持 PDF、Zotero、Mendeley、海量论文库检索。
- AI 自动续写：围绕当前文档和真实资料生成内容。
- 引用格式：支持大量引用样式，一键插入引用。
- 可核验声明：每个重要论断都能回到原始来源。
- 导出：支持 DOCX、LaTeX、HTML 等学术工作流格式。

对好编辑的启发：

- 不能只让 AI “写得像学术”，必须让每个引用和关键事实可追踪。
- 应增加“资料库”与“引用候选”视图，而不是把 RAG 只藏在后台。
- 小节写作时应显示“本节使用了哪些资料片段”。

### 2. Paperpal：学术写作质量控制套件

核心定位：All-in-one academic writing tool。

可借鉴能力：

- Research / Write / Cite 一体化。
- Chat PDF、论文检查、语言润色、改写、AI Review。
- Plagiarism checker、AI detector、citation generator。
- Word、Google Docs、Chrome、Overleaf 插件生态。
- 安全与合规标识，强化商业信任。

对好编辑的启发：

- 专著产品不能只有生成，还要有“检查中心”。
- 需要把质量检查拆成：格式、引用、术语、结构、重复、AI 痕迹、风险提示。
- 导出前应有“出版前体检报告”。

### 3. NotebookLM：资料驱动的知识工作台

核心定位：以用户资料为中心的 AI Research Tool & Thinking Partner。

可借鉴能力：

- 资料优先，而不是模型优先。
- 面向资料进行问答、总结、提纲、观点组织。
- 用户信任来自“回答基于我的资料”。

对好编辑的启发：

- 好编辑应提供“资料对话 / 资料摘要 / 资料映射到目录”的工作流。
- 大纲生成前应先分析资料库，生成“资料覆盖图谱”。
- 若资料不足，系统应明确提示哪些章节缺资料，而不是靠模型编。

### 4. Jasper：商业化 AI 工作流与品牌治理

核心定位：营销内容平台，但其“企业级 AI 工作流”值得借鉴。

可借鉴能力：

- Agents：面向任务的智能体，而不是单次聊天。
- Workflows / Pipelines：可重复执行的内容生产流程。
- Brand Voice、Style Guide、Knowledge、Governance。
- Prompt library、AI Studio、API / MCP。
- Trust Foundation：安全、权限、合规、治理。

对好编辑的启发：

- “专著写作”应被设计为多智能体流水线：规划员、研究员、写作者、引用核验员、审校员、格式员。
- 用户需要一个“风格指南”和“术语治理中心”。
- 商业化版本应逐步引入任务日志、失败重试、权限和审计。

### 5. Copy.ai：Playbook 与统一数据上下文

核心定位：AI-native workflow platform。

可借鉴能力：

- Playbooks：把最佳实践固化为可复用工作流。
- Unified data：统一资料、上下文和团队知识。
- 自动化管道：减少人工重复操作。

对好编辑的启发：

- 可以内置“专著写作 Playbook”：资料整理、选题论证、目录设计、分章生成、审校、导出。
- 不同书型可有不同 Playbook：学术专著、行业白皮书、教材、研究报告、政策研究。

### 6. QuillBot：模块化写作工具矩阵

核心定位：围绕写作的工具箱。

可借鉴能力：

- Paraphraser、Grammar Checker、Summarizer、Translator。
- AI Detector、Plagiarism Checker、Citation Generator。
- Chat PDF、Projects、Docs。

对好编辑的启发：

- 好编辑 2.0 可以保留专著主流程，同时增加小工具面板：改写、摘要、术语解释、标题优化、段落扩写、降重、引用格式化。
- 这些小工具应服务当前项目上下文，而不是孤立工具。

## 三、当前好编辑能力现状

### 已具备能力

1. 项目数据模型
   - [`ProjectKnowledgeBase`](../libriscribe/src/libriscribe/knowledge_base.py:131) 保存项目、章节、术语、引用、RAG 文档、风格指南等。
   - [`ChapterSection`](../libriscribe/src/libriscribe/knowledge_base.py:33) 已可承载四级目录小节、目标字数、状态、内容路径等。
   - [`Citation`](../libriscribe/src/libriscribe/knowledge_base.py:111) 已有基础引用结构。

2. AI 模型接入
   - [`LLMClient`](../libriscribe/src/libriscribe/utils/llm_client.py:21) 已支持官方与自定义 OpenAI 兼容平台。
   - 自定义模型已改为优先 raw HTTP，避免 SDK 被服务端拦截。

3. 大纲生成
   - [`_generate_outline_with_ai`](../libriscribe/src/libriscribe/web/app.py:1840) 支持全书大纲生成。
   - [`_generate_outline_chapter_by_chapter`](../libriscribe/src/libriscribe/web/app.py:1798) 支持分章稳定生成。
   - [`_improve_outline_with_ai`](../libriscribe/src/libriscribe/web/app.py:1895) 支持二次改进。

4. 章节写作
   - [`ChapterWriterAgent`](../libriscribe/src/libriscribe/agents/chapter_writer.py:25) 已从小说场景逻辑转向学术小节写作。
   - 支持按叶子小节生成、重试、补写、实时预览。
   - 普通章只输出本章小结，末章追加全书参考文献和术语表。

5. 学术提示词
   - [`ACADEMIC_MONOGRAPH_SYSTEM_PROMPT`](../libriscribe/src/libriscribe/utils/academic_prompt.py:1) 已提供统一专著写作原则、反幻觉引用规则和单章质量自检。

6. RAG 基础
   - [`DocumentLoader`](../libriscribe/src/libriscribe/rag/document_loader.py:29) 支持 PDF、DOCX、Excel、文本、HTML 加载。
   - [`Retriever`](../libriscribe/src/libriscribe/rag/retriever.py:36) 支持检索上下文。
   - [`VectorStore`](../libriscribe/src/libriscribe/rag/vector_store.py:18) 基于 ChromaDB。

7. 导出
   - [`DocxExporter`](../libriscribe/src/libriscribe/export/docx_export.py:12)、[`LatexExporter`](../libriscribe/src/libriscribe/export/latex_export.py:14)、[`PdfExporter`](../libriscribe/src/libriscribe/export/pdf_export.py:12) 已有基础导出。

### 关键短板

1. **引用链不完整**
   - [`Citation`](../libriscribe/src/libriscribe/knowledge_base.py:111) 缺 DOI、ISBN、作者、年份、标题、出版社、期刊、URL、访问日期、来源类型、页码范围、段落定位、证据片段 ID。
   - 正文引用与资料片段没有稳定绑定关系。
   - 没有“引用核验报告”。

2. **资料库不可视化不足**
   - 用户上传资料后，不清楚索引了哪些文档、切了哪些片段、每章覆盖哪些资料。
   - RAG 上下文进入提示词，但用户看不到证据来源。

3. **工作流仍偏页面按钮**
   - 当前有大纲、编辑、聊天、设置等页面，但没有完整的“专著生产流水线”。
   - 后台任务已有基础，但缺少任务日志、断点恢复、失败章节队列、全书质量汇总。

4. **审校体系不够商业化**
   - 目前已有章节评审和自评，但缺少导出前全书检查：引用、术语、标题层级、重复率、字数偏差、资料缺口、风险声明。

5. **提示词不可管理**
   - 目前提示词分散在代码和 YAML 中，用户不能在界面维护“提示词版本”。
   - 没有提示词测试、回滚、模板市场、书型模板。

6. **产品定位仍混有旧小说概念**
   - 代码中仍存在 [`Scene`](../libriscribe/src/libriscribe/knowledge_base.py:24)、旧 [`OutlinerAgent`](../libriscribe/src/libriscribe/agents/outliner.py:19) 和部分“角色/场景”兼容入口。
   - 2.0 应保留兼容，但 UI 与主流程彻底改为专著语言。

## 四、2.0 产品定位

建议 2.0 定位为：

> 面向中文学术专著、行业研究报告、教材与政策研究的 AI 专著生产工作台。以用户资料为可信来源，以章节流水线为生产核心，以引用核验和质量审校为商业可靠性保障。

2.0 不应只强调“AI 帮你写”，而应强调：

- 可控：目录、字数、风格、术语、引用均可配置。
- 可追溯：每个关键论断尽可能对应资料证据。
- 可恢复：长任务失败可续跑，不丢稿。
- 可审校：导出前自动体检。
- 可出版：DOCX/PDF/LaTeX 格式稳定，参考文献可管理。

## 五、2.0 功能架构设计

### 1. 项目驾驶舱

目标：让用户一眼看到整本书的生产状态。

功能：

- 全书目标字数、已生成字数、完成率。
- 章节完成度、小节完成度。
- 资料库数量、可用证据片段数量。
- 引用风险数量、资料缺口数量。
- 最近任务状态：运行中、失败、待重试、已完成。
- 一键操作：继续生成、生成缺失小节、运行全书体检、导出。

对应当前改造点：

- 优化 [`render_dashboard`](../libriscribe/src/libriscribe/web/app.py:1181)。
- 基于 [`_collect_chapters`](../libriscribe/src/libriscribe/web/app.py:1136) 扩展统计指标。

### 2. 资料库 / RAG 中心

目标：让用户管理所有真实来源。

功能：

- 上传 PDF、DOCX、TXT、HTML、Excel。
- 显示每个文档的索引状态、切片数量、页码/段落范围。
- 资料摘要：自动生成摘要、关键词、适用章节建议。
- 章节覆盖图谱：哪些章节有资料，哪些章节资料不足。
- 检索测试：输入问题，查看召回片段和分数。
- 证据收藏：将资料片段固定为某章/某节的证据。

对应当前改造点：

- 扩展 [`DocumentChunk`](../libriscribe/src/libriscribe/rag/document_loader.py:16) 元数据。
- 扩展 [`VectorStore.add_documents`](../libriscribe/src/libriscribe/rag/vector_store.py:51) 存储页码、段落、hash。
- 新增资料库页面，替代隐藏式 RAG。

### 3. 大纲规划器

目标：生成可执行、可写作、可控字数的大纲。

功能：

- 一键生成全书大纲。
- 稳定分章生成。
- 二次改进：补全缺章、平衡字数、统一术语、增加序言。
- 资料驱动大纲：根据资料库覆盖生成目录。
- 大纲质量检查：章数、编号、字数、层级、重复标题、资料缺口。
- 目录树拖拽 / 上下移动 / 合并拆分。

对应当前改造点：

- 强化 [`_outline_global_constraints`](../libriscribe/src/libriscribe/web/app.py:1770)。
- 在 [`_parse_outline_text`](../libriscribe/src/libriscribe/web/app.py:1581) 后增加结构校验报告。

### 4. 专著写作流水线

目标：把“生成章节”升级为可观察的生产任务。

推荐流水线：

1. 章节任务准备：读取目录、目标字数、前文摘要、术语表。
2. 资料检索：为每个小节检索证据片段。
3. 小节写作：按叶子节点生成正文。
4. 引用核验：检查正文中每个引用是否存在证据。
5. 字数补齐：不足时只扩展已有资料和理论分析，不编资料。
6. 章节小结：普通章只总结本章。
7. 单章评分：结构、字数、术语、引用、风险。
8. 保存与版本记录。

对应当前改造点：

- 重构 [`_bg_write_book`](../libriscribe/src/libriscribe/web/app.py:2276) 为可恢复任务。
- 扩展 [`ChapterWriterAgent._write_academic_chapter`](../libriscribe/src/libriscribe/agents/chapter_writer.py:91) 的中间产物记录。
- 新增“失败小节重试队列”。

### 5. 引用与事实核验中心

目标：彻底解决“引用幻觉”和“来源不可查”。

功能：

- 引用列表：按全书/章节/小节查看真实引用。
- 引用字段：作者、年份、标题、来源、DOI/ISBN/URL、页码、原文摘录、引用格式。
- 正文扫描：识别 `[1]`、作者年份、法规标准号等。
- 核验结果：通过、缺来源、疑似幻觉、格式错误、页码缺失。
- 自动修复：删除无证据引用、替换为“资料不足”提示、生成引用候选。
- 导出时统一编号。

建议扩展数据模型：

```python
class SourceDocument(BaseModel):
    id: str
    title: str = ""
    authors: list[str] = []
    year: str = ""
    source_type: str = "pdf"
    file_path: str = ""
    doi: str = ""
    isbn: str = ""
    url: str = ""
    metadata: dict = {}

class EvidenceChunk(BaseModel):
    id: str
    document_id: str
    text: str
    page_start: int | None = None
    page_end: int | None = None
    paragraph_index: int | None = None
    chunk_hash: str = ""

class Citation(BaseModel):
    id: str = ""
    evidence_chunk_id: str = ""
    sentence: str = ""
    source: str = ""
    page: int | None = None
    quote_original: str = ""
    formatted_ref: str = ""
    style: str = "GB/T 7714"
    confidence: float = 0.0
    status: str = "unverified"
```

### 6. 审校与质量中心

目标：导出前提供商业化体检。

检查项：

- 章节结构完整性：是否缺章、缺节、编号错乱。
- 字数偏差：全书、章节、小节。
- 术语一致性：同义词混用、关键术语缺定义。
- 引用完整性：引用是否真实、编号是否连续。
- 资料覆盖度：每章资料数量、低证据章节。
- 重复内容：章内/章间重复段落。
- AI 风格风险：空泛套话、模板句、虚假“研究发现”。
- 格式规范：标题层级、缩进、参考文献、附录。

对应当前改造点：

- 扩展 [`self_assess_chapter`](../libriscribe/src/libriscribe/utils/academic_prompt.py:144)。
- 新增全书级 `BookReviewReport`。
- 强化 [`ContentReviewerAgent`](../libriscribe/src/libriscribe/agents/content_reviewer.py:13) 从小说审查转为专著审校。

### 7. 提示词中心 / Prompt Studio

目标：让提示词可管理、可测试、可版本化。

提示词分层：

1. 全书宪法 Prompt：定位、风格、术语、引用红线、结构规范。
2. 大纲规划 Prompt：章数、字数、层级、序言、全书逻辑。
3. 小节写作 Prompt：当前小节、目标字数、证据片段、前文摘要。
4. 引用核验 Prompt：只判断证据是否支持论断。
5. 章节审校 Prompt：评分、风险、修改建议。
6. 改写润色 Prompt：不改事实、不改引用、不新增资料。
7. 导出前检查 Prompt：全书格式和出版风险。

功能：

- 内置模板：学术专著、教材、行业白皮书、政策研究、企业报告。
- 用户自定义模板。
- Prompt 版本记录与回滚。
- 测试输入与输出对比。
- 变量说明：`{project_title}`、`{chapter_title}`、`{section_outline}`、`{evidence_chunks}` 等。

对应当前改造点：

- 整合 [`prompts/templates`](../libriscribe/prompts/templates/chapter_writer.yml:1) 与代码内提示词。
- 扩展 [`ExternalPromptMixin`](../libriscribe/src/libriscribe/utils/prompt_integration.py:6)。

### 8. 导出与出版中心

目标：从“生成文件”升级为“出版前交付”。

功能：

- DOCX：中文字体、标题样式、目录、页眉页脚、参考文献。
- PDF：中文稳定渲染、封面、目录、分页。
- LaTeX：ctex 支持、参考文献区、附录。
- Markdown：便于继续编辑。
- 导出前强制体检：严重引用风险时提示用户确认。
- 导出包：正文、参考文献、术语表、质量报告、资料清单。

对应当前改造点：

- 强化 [`DocxExporter`](../libriscribe/src/libriscribe/export/docx_export.py:12)、[`PdfExporter`](../libriscribe/src/libriscribe/export/pdf_export.py:12)、[`LatexExporter`](../libriscribe/src/libriscribe/export/latex_export.py:14)。

## 六、2.0 提示词策略升级

### 1. 全书宪法 Prompt

用途：所有阶段共享，不直接生成正文。

核心规则：

- 这是学术专著，不是论文、报告、小说。
- 不得改变用户目录和章节编号。
- 不得编造引用、法规、标准、作者、年份、机构报告。
- 没有资料时必须标记“信息缺失”。
- 普通章不输出全书附录；末章统一输出全书参考文献和术语表。
- 全书术语、语气、段落格式、标题层级一致。

### 2. 证据约束 Prompt

用途：写作前注入资料片段。

模板方向：

```text
你只能把下列证据片段作为事实来源。若片段不足以支持某个事实判断，不得编造；应改写为理论分析或标记【信息缺失】。
每条证据格式为：证据ID、来源文档、页码/段落、原文摘录。
正文中如使用证据，必须在内部记录 evidence_id；只有存在 evidence_id 的内容才允许生成引用标记。
```

### 3. 小节写作 Prompt

用途：叶子小节生成。

关键输入：

- 全书主题。
- 当前章节目标。
- 当前小节标题、编号、目标字数。
- 父级标题链。
- 前文摘要。
- 术语表。
- 证据片段。
- 禁止事项。

### 4. 引用核验 Prompt

用途：写完后逐条核查。

输出结构：

```json
{
  "claims": [
    {
      "claim": "正文中的事实性论断",
      "supported": true,
      "evidence_ids": ["ev_001"],
      "risk": "low",
      "action": "keep"
    }
  ]
}
```

### 5. 审校 Prompt

用途：不重写全文，只给结构化报告。

评分维度：

- 结构完整性 10 分。
- 字数达成 10 分。
- 术语一致 10 分。
- 论证质量 10 分。
- 引用可信 10 分。
- 资料覆盖 10 分。
- 出版格式 10 分。

### 6. 改写 Prompt

用途：局部优化。

红线：

- 不新增事实。
- 不新增引用。
- 不改变标题编号。
- 不删除用户指定术语。
- 不把“信息缺失”改成确定性结论。

## 七、分阶段实施路线图

### 阶段 0：清理产品定位与技术债（1-2 天）

目标：让主流程彻底转为专著产品。

任务：

- 隐藏或弱化 UI 中旧小说“角色/场景”概念。
- 检查 [`i18n.py`](../libriscribe/src/libriscribe/web/i18n.py:9) 的所有旧文案。
- 梳理现有页面导航：项目首页、资料库、大纲、写作、审校、导出、模型配置。
- 为后续 2.0 页面预留路由和状态字段。

验收：

- 用户不再看到“场景列表/角色”等影响专著理解的主流程文案。
- 当前功能不回退。

### 阶段 1：资料库可视化与引用模型升级（3-5 天）

目标：建立可信资料链。

任务：

- 新增 `SourceDocument`、`EvidenceChunk` 数据模型。
- 扩展 `Citation` 字段。
- 上传资料后显示文档清单、索引状态、切片数量。
- 检索测试页面：展示召回片段、来源、分数。
- 写作时记录每节使用的证据片段。

验收：

- 用户能看到资料是否被成功索引。
- 每个小节可查看关联资料片段。
- 没有资料时系统明确提示，不伪造引用。

### 阶段 2：专著生产流水线与断点恢复（3-6 天）

目标：长任务商业化可靠运行。

任务：

- 将全书生成拆为任务队列：章任务、小节任务、审校任务、导出任务。
- 增加任务日志：开始时间、结束时间、模型、失败原因、重试次数。
- 小节级状态：pending、running、completed、failed、needs_review。
- 支持“继续生成缺失小节”“只重试失败小节”。
- 后台任务进度持久化到项目文件。

验收：

- 页面刷新或关闭后，任务状态可恢复。
- 某个小节失败不影响全书，失败原因可见。
- 用户可一键继续。

### 阶段 3：引用核验与全书质量中心（4-7 天）

目标：上线出版前体检。

任务：

- 正文引用扫描。
- 引用与证据片段匹配。
- 生成章节质量报告和全书质量报告。
- 检查字数、标题层级、术语、重复段落、资料缺口。
- 导出前显示风险报告。

验收：

- 无证据引用能被识别。
- 严重风险在导出前提示。
- 报告可随导出包下载。

### 阶段 4：Prompt Studio 与模板体系（3-5 天）

目标：让提示词可管理。

任务：

- 将核心提示词从代码硬编码逐步迁移到模板文件。
- 新增提示词中心页面。
- 支持模板查看、编辑、恢复默认、测试。
- 内置书型模板：学术专著、行业报告、教材、政策研究。
- 支持提示词版本号写入任务日志。

验收：

- 用户能调整提示词而不改代码。
- 出问题能回滚默认模板。
- 任务日志记录使用的提示词版本。

### 阶段 5：导出与商业化包装（3-6 天）

目标：提高交付质量和产品信任。

任务：

- DOCX 样式增强：标题、正文、引用、附录、目录。
- PDF 封面、目录、中文字体稳定化。
- 导出包：正文 + 质量报告 + 资料清单 + 引用表。
- 商业化 UI：工作台、进度卡片、风险卡片、操作引导。
- 增加配置备份、错误日志下载。

验收：

- 用户能拿到可继续编辑和可交付的文件包。
- 导出失败原因明确。
- 视觉和流程接近商业产品。

## 九、建议的 2.0 技术架构

### 当前阶段适合的轻量架构

继续保留 Streamlit，但把状态和任务做扎实：

- 项目文件仍用 JSON + Markdown。
- RAG 使用 ChromaDB 本地库。
- 后台任务使用线程 + 持久化任务日志。
- 提示词使用 YAML/Markdown 模板文件。
- 质量报告使用 JSON + Markdown 双格式。

优点：改造快，适合当前产品验证。

### 中长期架构

当进入多用户商业运营时，建议迁移到：

- FastAPI 后端。
- PostgreSQL 保存项目、任务、引用、权限。
- Redis / Celery 或 RQ 处理长任务。
- 对象存储保存资料和导出文件。
- 前端使用 Next.js 或保持 Streamlit 管理端。
- 向量库可选 Chroma、Qdrant、Milvus。
- 模型网关统一管理 OpenAI、Claude、自定义模型、国产模型。

## 十二、最终判断

好编辑 2.0 的竞争点不应是“比通用 AI 更会写”，而是：

- 比通用 AI 更懂专著结构；
- 比普通写作工具更可控；
- 比聊天机器人更能长期生产；
- 比简单 RAG 工具更重视引用与出版；
- 比本地脚本更接近商业工作台。

因此，2.0 的产品口号可以是：

> 让 AI 专著写作从“能生成”升级为“可追溯、可审校、可交付”。
