# DOC/OLE 二进制乱码证据片段修复补充

## 摘要

本次补充修复了资料库/RAG 中历史乱码仍在 UI 显示的问题。原因不是单一解析器问题，而是三类状态残留共同导致：

1. 已写入项目内存会话 `st.session_state["project_data"]` 的旧证据片段；
2. 已持久化到 ChromaDB 的历史乱码向量；
3. 资料库页面展示和检索时没有二次过滤旧数据。

已完成以下处理：

- 清空 ChromaDB 中 28 条历史乱码向量，验证 `chroma_count_verify 0`。
- 在资料库页面渲染时自动清理项目中的乱码资料和证据片段，并落盘保存。
- 在 RAG 检索结果展示前过滤历史乱码向量，避免旧索引再次污染 UI。
- 在上传索引入口再次过滤不可用 chunk，防止二进制/OLE/WPS 结构文本进入证据库。
- 强化 `DocumentLoader` 对 `Root Entry`、`WordDocument`、`Normal.dotm`、`WPS Office`、大量 `���/þÿÿ` 的识别。
- 重启 Streamlit，使旧会话状态重新加载。

  - 已清空历史 ChromaDB collection，移除 28 条乱码向量。
