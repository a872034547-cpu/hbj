# 章节一写多断尾续写与 token 预算修复

## 摘要

修复“一写多”生成多个小节时正文尾句仍可能停在半句话的问题。此次没有恢复任何强制截断或裁剪逻辑，而是从生成预算和断尾兜底两侧处理：提高小节生成、重试、质量重写、续写扩展与自定义 OpenAI-compatible 回退请求的 token 预算；当最终正文没有以完整句末结束时，仅追加缺失续写，不删除、不改写、不压缩原文。

## 变更文件

- `libriscribe/src/libriscribe/agents/chapter_writer.py`
  - 提高小节初稿、稳定重试、精简提示重试、质量门禁重写、扩展续写的输出 token 预算。
  - 新增未闭合句尾检测与 `_complete_truncated_tail` 追加式补全。
  - 在小节写入前执行断尾补全，并再次进行格式规范；仍保持“不按字数裁剪正文”的策略。
  - 恢复提示词中“每章至少安排三处明确批评”的强约束。

- `libriscribe/src/libriscribe/utils/llm_client.py`
  - 调整自定义 OpenAI-compatible SDK/Responses/raw HTTP fallback 的 token 预算，不再在长文生成时降到 2500/1200 这类过小输出上限。

- `libriscribe/tests/test_commercial_routes.py`
  - 增加断尾只追加、不裁剪原文的回归测试。
  - 增加完整句尾不触发补全的测试。
  - 增加长小节生成预算测试。
  - 增加自定义 LLM fallback 不再降到小 token 预算的测试。
