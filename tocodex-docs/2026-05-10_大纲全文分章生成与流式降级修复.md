# 大纲生成完整性与流式降级修复

## 摘要

本次修复针对 AI 大纲只生成第一章的问题，重构大纲生成入口，新增全文生成、分章生成、二次改进和序言选项，并加入章节数量校验；当一次生成章节不足时会自动切换为分章生成，避免模型把全部 token 消耗在第一章。

同时修复自定义 OpenAI 兼容模型在章节写作/聊天等流式调用中被中转站拦截的问题：流式请求失败后自动降级到非流式 `generate_content`，复用已验证可用的 raw HTTP 兜底路径，避免章节写作全部失败。

## 修改文件

- `libriscribe/src/libriscribe/web/app.py`
  - 大纲页面新增生成模式选择：全文一次生成、分章生成（更稳）、二次改进现有大纲。
  - 新增“包含序言（全书逻辑起点与最终归宿）”选项。
  - 新增大纲完整性校验 `_count_outline_chapters()`。
  - 新增目标字数/章数计算 `_outline_target_settings()`。
  - 新增分章生成 `_generate_outline_chapter_by_chapter()`。
  - 新增二次改进 `_improve_outline_with_ai()`。
  - `_parse_outline_text()` 支持 `persist/rerun/show_messages` 参数，便于内部流程一次性生成后再统一保存和刷新。
  - 聊天入口改为统一走 `LLMClient.generate_content()`，避免直接调用 SDK 被拦截。
  - 更新 `client_code_version`，强制 Streamlit 旧会话自动刷新 LLMClient，无需手动重启。

- `libriscribe/src/libriscribe/utils/llm_client.py`
  - `stream_content()` 增加异常降级：OpenAI SDK 流式请求被拦截时，自动切换到非流式 `generate_content()`。
  - 自定义模型可继续使用 raw HTTP 兜底路径返回正文。

## 验证

- 已运行语法检查：
  - `python -m py_compile src\\libriscribe\\web\\app.py src\\libriscribe\\utils\\llm_client.py`
- 已验证大纲解析：包含序言的 3 章样例可正确解析为章节 `[1, 2, 3]`。
- 已验证真实模型烟测：`gpt-5.5` 在 SDK 被拦截的情况下通过 raw HTTP 返回完整大纲，章节统计为 3，且包含序言。
- 已验证流式降级：`stream_content()` 在 SDK 流式请求被拦截后自动降级并返回“流式降级OK”。
