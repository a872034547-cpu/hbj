# 结构化 JSON 专业 Word 导出脚本四级标题与页眉页脚更新

## 摘要

根据最新 Word 导出规范，重写独立脚本，使用 `python-docx` 将结构化 JSON 导出为专业排版 `.docx` 文档。新版脚本硬编码封面、目录、前言、正文、结语、参考文献的页面结构、页码、页眉页脚、标题样式、正文样式、参考文献样式与四级中文标题编号。

## 变更文件

- `libriscribe/scripts/export_structured_json_to_docx.py`
  - 重写为完整独立 CLI 脚本。
  - 支持 `title`、`author`、`preface`、`chapters[].sections[].level3[].level4[]`、`conclusion`、`global_references` 结构。
  - 增加 Heading 1-4 四级中文编号：`第一章`、`第一节`、`一、`、`（一）`。
  - TOC 更新为 `TOC \\o "1-4" \\h \\z \\u`。
  - 固定 A4、上下 2.54cm、左右 3.18cm。
  - 固定正文、标题、参考文献样式，并添加中英数字间 U+2009 细空格预处理。
  - 设置封面无页眉页脚；目录/前言使用小写罗马页码；正文从阿拉伯数字 1 开始。
  - 设置正文奇偶页页眉页脚：奇数页当前章，偶数页书名，奇数页码右侧，偶数页码左侧。

- `libriscribe/tests/test_export_and_quality_gate_services.py`
  - 将结构化 JSON Word 导出测试更新到新规范。
  - 覆盖 `level3` / `level4` 输入、Heading 4 样式、3.18cm 页边距、Heading 2 居中、Heading 3/4 首行缩进、Reference 10.5pt 与悬挂缩进。

## 追加修复

- 移除了脚本中对不存在模块 `docx.enum.page` 的依赖，改为直接通过 `w:pgNumType` XML 设置 `decimal` / `lowerRoman` 页码格式，确保当前 `python-docx 1.2.0` 环境可直接运行。
- 修复中英数字细空格替换中的 `bad escape \\u` 问题，改用 `lambda` 安全插入 U+2009。
- 保留 `export_json_data_to_docx()`、`export_json_to_docx()` 与 `generate_monograph` 兼容入口，既可命令行使用，也可被网页导出和测试导入。
- 针对实际生成 Word 后出现 `第1章`、`第1节`、`1.1` 和空白页偏多的问题，取消 Word 自动多级编号，改为脚本写入纯文本中文编号，并清除 Heading 样式/段落上的 `w:numPr`。
- 章节换页由 `WD_SECTION.ODD_PAGE` 改为 `WD_SECTION.NEW_PAGE`，避免为强制奇数页自动插入空白页。
- 取消标题 `keepNext`，降低小节标题把后续正文整体推到下一页造成大块空白的风险。
- 增强输入标题编号清洗，输入里已有 `第1章`、`1.1`、`一、`、`（一）` 时不会与脚本编号重复。
