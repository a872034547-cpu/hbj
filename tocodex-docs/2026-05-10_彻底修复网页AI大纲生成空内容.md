# 彻底修复网页 AI 大纲生成空内容

## 摘要

用户反馈在线检测可用后，网页侧点击 AI 生成大纲仍提示“AI 未返回可用大纲/模型返回空内容”。本次继续核实完整大纲生成链路，而不是只验证短提示检测。

排查结论：

1. `gpt-5.5` 配置正确，模型确实可用。
2. `openai-python` SDK 请求会被目标中转服务拦截，返回 `Your request was blocked.`。
3. `requests.post` 原始 HTTP 兜底调用可以成功返回大纲。
4. 网页仍可能复用 Streamlit `session_state` 中旧的 `LLMClient` 实例，导致代码修复后页面还在用旧调用链。
5. 大纲长提示链路已实际验证：返回非空大纲，并成功解析出 2 个章节。

## 变更文件

- `libriscribe/src/libriscribe/web/app.py`
  - `get_llm_client()` 增加模型配置签名缓存。
  - 当模型配置、API Base、模型名或密钥尾段变化时，自动重建 `LLMClient`，避免 Streamlit 旧会话缓存继续使用旧客户端。
  - AI 生成大纲如果首次返回空，自动强制重建客户端并立即重试一次。
  - 大纲空响应错误信息改为显示真实接口诊断，不再笼统要求用户重新检查 API Base/模型名/密钥。

- `libriscribe/src/libriscribe/utils/llm_client.py`
  - 原始 HTTP 兜底调用成功返回正文后，清空旧的 `last_error`，避免页面把前面 SDK 被拦截的错误误认为最终失败原因。

## 验证结果

已执行：

```cmd
python -m py_compile src\libriscribe\utils\llm_client.py src\libriscribe\web\app.py
```

结果：通过。

已执行完整大纲生成 smoke test：

- 使用本地配置中的 `gpt-5.5`。
- 使用与网页 `_generate_outline_with_ai()` 同类型的长提示。
- `max_tokens=6000`，`temperature=0.4`。
- 结果：
  - `raw_len 1697`
  - `norm_len 1696`
  - `chapters 2`
  - `chapter_keys [1, 2]`
  - `last_error` 为空

说明：模型不仅短提示可用，网页大纲生成所需的长提示也已经核实可用，并能解析为章节。
