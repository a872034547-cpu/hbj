# RAG 索引依赖与 DOCX 兜底修复

## 问题

用户上传参考文档索引时出现：

```text
RAG 模块不可用: chromadb is required. Install with: pip install chromadb
```

安装 `chromadb` 后继续验证发现两个运行级问题：

1. ChromaDB 1.x 不接受空 metadata：

```text
ValueError: Expected metadata to be a non-empty dict, got 0 metadata attributes in add.
```

2. 用户上传的部分 `.docx` 文件不是合法 DOCX ZIP 包，解析报错：

```text
not a ZIP archive (so not a DOCX file)
```

## 修改

- 已安装运行依赖：`chromadb==1.5.9`。
- 修改 [`libriscribe/src/libriscribe/rag/vector_store.py`](../libriscribe/src/libriscribe/rag/vector_store.py)：
  - `_sanitize_metadata()` 现在会确保返回非空标量 metadata。
  - 对没有元数据的分块补充 `source="unknown"`，兼容 ChromaDB 1.x。
- 修改 [`libriscribe/src/libriscribe/rag/document_loader.py`](../libriscribe/src/libriscribe/rag/document_loader.py)：
  - `_load_docx()` 现在优先使用 `unstructured` / `python-docx` 解析真实 DOCX。
  - 如果文件扩展名是 `.docx` 但实际不是 ZIP 包，会自动尝试按文本读取。
  - 增加 `_load_text_fallback()`，支持 `utf-8`、`utf-8-sig`、`gb18030`、`gbk`、`latin-1` 多编码兜底。

## 已验证

语法检查：

```text
python -m py_compile src\libriscribe\rag\document_loader.py src\libriscribe\rag\vector_store.py src\libriscribe\web\app.py
```

依赖和向量库初始化：

```text
chromadb ok 1.5.9
imports ok
embedding dimension 384
vectorstore ok count 0
```

向量写入和查询 smoke test：

```text
vector_smoke_ok 0 1
```

说明 ChromaDB、EmbeddingProvider、VectorStore 写入/查询链路可运行。`added=0` 是因为同一 smoke test chunk 已在上一次验证中写入，查询仍返回 1 条结果。

误命名 DOCX 兜底解析验证：

```text
unstructured DOCX parsing failed for tmp_fake_docx.docx: not a ZIP archive ... trying python-docx/text fallback
python-docx parsing failed for tmp_fake_docx.docx ... trying text fallback
Loaded tmp_fake_docx.docx as plain text fallback because it is not a valid DOCX package
fake_docx_chunks 1 tmp_fake_docx.docx
```

Streamlit 已重启：

```text
python -m streamlit run src/libriscribe/web/app.py --server.port 8501 --server.headless true
Local URL: http://localhost:8501
```

## 说明

如果上传的文件确实是损坏的二进制 DOCX，兜底文本读取也只能尽量提取可解码文本；建议后续 UI 明确提示“文件不是合法 DOCX，可尝试另存为 DOCX/PDF/TXT 后重新上传”。
