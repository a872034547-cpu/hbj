# AI 配置保存与自定义平台连接修复

## 本次修复内容

### 1. 修复 AI 配置保存失败
问题：旧 `ProjectKnowledgeBase` 实例来自旧类定义，直接执行属性赋值（如 `project.custom_api_base = ...`）会触发 Pydantic `ValueError`。

修复：在 [`app.py`](libriscribe/src/libriscribe/web/app.py:1524) 中改为：
- 先用 `project.model_dump()` 转成字典
- 更新 `llm_provider/custom_api_base/custom_api_key/custom_model`
- 再通过 `ProjectKnowledgeBase.model_validate(data)` 重建新对象
- 回写到 `st.session_state["project_data"]`

这样避免对旧实例直接赋新字段。

### 2. 修复旧 session 项目对象兼容性检测
在 [`app.py`](libriscribe/src/libriscribe/web/app.py:97) 的 `init_session_state()` 中：
- 不再只用 `hasattr()` 判断
- 改为实际访问 `project.custom_api_base`
- 捕获 `AttributeError` / `ValueError`
- 一旦发现旧对象，自动调用 [`ProjectKnowledgeBase.load_from_file`](libriscribe/src/libriscribe/knowledge_base.py:298) 重新加载

### 3. 增强自定义 AI 连接测试
在 [`app.py`](libriscribe/src/libriscribe/web/app.py:1496) 中：
- 增加 API Base URL / API Key / 模型名的前置校验
- 抽出 `_do_test_connection()`
- 自动规范化 base URL，若未以 `/v1` 结尾则自动补全
- 增加更明确的报错提示：网络错误、401 认证失败、404 模型不存在、空响应
