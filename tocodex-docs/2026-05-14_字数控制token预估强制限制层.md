# 字数控制 token 预估强制限制层

## 摘要
- 在章节小节生成流程中新增基于历史 `(tokens, chinese_words)` 的 token 上限预估层。
- 保留原有“两轮 AI 协商补写/压缩”流程；若两轮后仍超标，追加一次服务端 `max_tokens` 限制生成，不把 token 限制写入提示词。
- 若 token 限制生成后仍严重超标，不再抛错阻塞全书生成，而是标记 `word_count_soft_fail` 并记录目标/实际字数和复核说明。
- 全流程不使用代码裁剪正文，所有正文仍由 AI 完整生成。

## 变更文件
- `libriscribe/src/libriscribe/utils/llm_client.py`
  - 新增最近一次调用的 `usage`、`completion_tokens`、`total_tokens` 捕获能力。
  - OpenAI/OpenRouter/Claude/DeepSeek/Mistral/自定义 OpenAI-compatible raw HTTP 路径均尽量记录 token usage。
- `libriscribe/src/libriscribe/agents/chapter_writer.py`
  - 新增 token 估算、历史记录、token cap 估算和 `generate_with_token_cap`。
  - `_repair_word_count_loop` 改为三阶递进：普通修正 2 轮 → token cap 压缩 1 次 → soft fail 放行。
  - 移除严重超标时的阻塞异常，改为小节软失败标记。
- `libriscribe/src/libriscribe/knowledge_base.py`
  - `ChapterSection` 增加 `word_count_status`、`word_count_target`、`word_count_actual`、`word_count_note` 字段，并兼容旧项目加载。
- `libriscribe/src/libriscribe/web/app.py`
  - 写章节页面为 `word_count_soft_fail` 小节显示黄色复核提醒。
- `libriscribe/src/libriscribe/services/quality_service.py`
  - 将 `word_count_soft_fail` 视为已完成写作单元，避免质量统计阻塞。
- `libriscribe/src/libriscribe/services/outline_service.py`
  - 大纲统计将 `word_count_soft_fail` 计入已完成叶子小节。
- `libriscribe/src/libriscribe/services/pipeline_service.py`
  - 写作流程状态将 `word_count_soft_fail` 计入已开始/已完成，避免流程卡住。
