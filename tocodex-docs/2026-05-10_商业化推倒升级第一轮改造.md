# 商业化推倒升级第一轮改造备忘

## 摘要

本轮落实 Libriscribe / 好编辑商业化升级的第一层地基：在不破坏现有 Streamlit 单体功能的前提下，新增后端服务层骨架、扩展前端商业化路由、建立测试门禁，并保留旧版大纲、资料库、章节写作、聊天助手、设置和模型配置入口的兼容映射。

## 已完成改造

1. 新增 `services/` 服务层骨架，开始把项目读写、任务、导出、质量、引用、资料、大纲、流水线、提示词和审计能力从 UI 中解耦。
2. 将 Web 导航从旧工具页集合升级为商业化信息架构：项目驾驶舱、项目组合、资料库/RAG、大纲规划、生产流水线、章节写作、引用核验、质量中心、提示词中心、出版交付、写作工具箱、项目设置、模型配置、审计中心。
3. 新增页面骨架并在关键页面接入服务层指标，形成项目状态、流水线状态、引用风险、质量体检、Prompt Playbook 和出版交付入口。
4. 保留旧功能入口兼容：`Dashboard` 映射到 `Workspace`，`Chat` 映射到 `Tools`，避免历史会话状态或旧页面名导致路由失效。
5. 新增 pytest 测试地基，覆盖质量服务、任务服务、大纲与流水线服务的基础契约。
6. 将 `pytest>=8.0.0` 加入依赖，作为后续上线门禁的一部分。

## 下一阶段建议

1. 将 `app.py` 中项目读写、导出、任务调度逐步迁移到服务层。
2. 把任务中心升级为持久化 JSONL/SQLite，支持断点续跑和失败重试。
3. 将 RAG 检索结果稳定写入 `EvidenceChunk` 与 `Citation`，形成正文—证据—引用闭环。
4. 扩展测试到导出、RAG 索引、大纲解析、章节生成降级和 Streamlit 冒烟测试。
