# 修复 AI 自定义模型保存与全流程检测

## 摘要

本次修复了 AI 自定义模型档案保存失败及配置文件损坏后无法读取的问题，并执行了关键链路烟测。问题根因包括：编辑已有模型时密码输入框可能提交为空，以及模型配置文件曾出现相邻 JSON 对象缺少逗号导致解析失败。

## 变更文件

- `libriscribe/src/libriscribe/web/app.py`
  - 编辑已有模型档案时，API 密钥输入框允许留空并沿用已保存密钥。
  - 新增模型档案去重与字段归一化逻辑，避免同一自定义模型重复保存。
  - `_load_model_profiles()` 增加 JSON 损坏恢复能力：对漏逗号的相邻对象进行修复，并保存 `.bak` 备份。
  - `_save_model_profiles()` 改为临时文件原子替换，降低写入中断导致配置损坏的风险。

- `libriscribe/config/model_profiles.json`
  - 已自动修复为合法 JSON。
  - 自定义 `gpt-5.5` 模型档案去重后保留 1 条可用配置。

## 检测结果

- `python -m py_compile` 检查通过：
  - `src/libriscribe/web/app.py`
  - `src/libriscribe/utils/llm_client.py`
  - `src/libriscribe/export/pdf_export.py`
  - `src/libriscribe/rag/embeddings.py`
- 模型配置加载通过：共 7 个模型档案，自定义 `gpt-5.5` 保留 1 个。
- 大纲规范化烟测通过：一行式 AI 输出可切分为章、节、三级目录行。
- 中文 PDF 导出烟测通过：生成文件大小 12448 字节。
- RAG 文档解析烟测通过：TXT 文档可成功分块并带有来源元数据。

## 备注

- 修复过程中生成了 `libriscribe/config/model_profiles.json.bak`，用于保留损坏配置修复前的备份。
- 模型配置文件包含 API 密钥，不应提交到公开仓库；如该密钥是真实可用密钥，建议后续在服务商后台轮换一次。
