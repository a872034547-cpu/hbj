## 基于 GPT-5.4/5.5 Agent 一体化“一小时写书”的工作流升级方案

### 0. 总体判断

你这次不是要再加一个按钮，而是要把现在的“项目 / 资料 / 大纲 / 编辑器”改成**用户一眼能懂的一小时写书闭环**。

当前项目已有可用地基：

- [`PipelineService`](libriscribe/src/libriscribe/services/pipeline_service.py:26) 已有阶段化流水线，但现在还是传统 `项目立项 → 资料入库 → 大纲规划 → 正文初稿...`。
- [`render_workspace_page()`](libriscribe/src/libriscribe/web/app.py:3731) 已有项目驾驶舱，但还没有按“一小时写书”展示。
- [`render_pipeline_page()`](libriscribe/src/libriscribe/web/app.py:3765) 目前只展示阶段卡片，没有细分到用户每一步要做什么。
- [`ChapterWriterAgent`](libriscribe/src/libriscribe/agents/chapter_writer.py:25) 已经支持按四级目录写作单元逐节生成。
- [`CitationService`](libriscribe/src/libriscribe/services/citation_service.py:13) 已新增参考文献解析和核验入口，可作为后续 OpenAlex API 接入点。

因此推荐采用：**先重构前端工作流和服务层视图，不立即大改底层生成引擎**。这样可以让用户马上看到清晰路径，同时不破坏现有大纲、RAG、章节生成、导出能力。

## 1. 新产品主线：一小时写书 6 步闭环

把现有写书流程升级为：

1. **需求理解与选题策展**
   - 用户输入书名、方向、目标读者、书型、字数、用途。
   - Agent 自动整理“为什么写、写给谁、解决什么问题、全书价值主张”。
   - 输出：项目定位卡、写作目标、风格约束。

2. **文献 / 知识库注入**
   - 支持上传资料。
   - 支持粘贴参考文献。
   - 预留 OpenAlex 等文献检索 API。
   - 输出：资料库、证据片段、参考文献候选、未核验风险。

3. **结构化大纲生成**
   - 基于需求与资料生成 `章—节—一、—（一）—写作思路`。
   - 支持全书生成、分章生成、单章修改。
   - 输出：可解析四级目录、每节写作边界、字数规划。

4. **正文逐章撰写**
   - 基于知识库、证据片段、章节上下文逐章 / 逐小节生成。
   - 强制自我一致性检查、术语一致、上下文章际衔接。
   - 引用必须来自资料库或核验记录，不能凭空编造。

5. **图文同步生成（可选）**
   - 作为二次润色优化阶段，不默认自动生成。
   - 用户可选择：流程图、路线图、表格、对比矩阵、章节概念图。
   - 基于已生成正文生成，不打断主写作流程。

6. **全书交付与版本管理**
   - 导出 DOCX / PDF / LaTeX / Markdown / PPTX。
   - 保存版本、质量报告、引用清单、资料清单。
   - 输出出版级交付包。

## 2. 页面与功能项重构

### 2.1 侧边导航建议改成用户能懂的 6 步

当前导航可以保留内部路由，但显示文案建议改为：

1. `① 选题与项目`
   - 对应现有 Projects / Workspace。
2. `② 资料与检索`
   - 对应 Sources。
3. `③ 大纲与结构`
   - 对应 Outline。
4. `④ 一小时写书`
   - 对应 Pipeline，升级为主工作流页。
5. `⑤ 正文编辑`
   - 对应 Editor。
6. `⑥ 审校与交付`
   - 汇总 Citations / Quality / Exports。
7. `全局提示词`
   - 对应 Prompts。
8. `模型设置`
   - 对应 AIConfig。

这样用户不会被“Pipeline / Citations / Quality”等英文或平台术语吓住。

  - `生成/优化项目定位`

## 3. 后端服务升级方案

### 3.1 升级 [`PipelineService`](libriscribe/src/libriscribe/services/pipeline_service.py:26)

将现有 8 阶段改成用户说的 6 步闭环：

1. `briefing`：需求理解与选题策展。
2. `knowledge_injection`：文献/知识库注入。
3. `outline_planning`：结构化大纲生成。
4. `draft_writing`：AI 正文逐章撰写。
5. `visual_polish`：图文同步生成，可选。
6. `delivery`：全书交付与版本管理。

同时每个阶段返回：

- `user_action`：用户要做什么。
- `agent_action`：AI 自动做什么。
- `output`：产出物。
- `status`：pending / in_progress / completed / blocked / optional。
- `primary_route`：跳转页面。
- `primary_action`：按钮文案。

### 3.2 新增 Agent Workflow 服务

建议新增：

- 后续承接 OpenAlex API 和多模态图文生成配置。

## 5. 图文同步生成的产品策略

按你的判断，图文同步生成不应该放在主写作步骤里强制执行，应该设计成：

- 默认关闭。
- 位于“二次润色 / 优化”阶段。
- 用户按章节选择是否生成。
- 图表类型包括：
  - 技术路线图。
  - 章节结构图。
  - 对比表。
  - 指标体系表。
  - 流程图。
  - 政策 / 技术 / 应用场景矩阵。
- 第一版输出 Markdown 表格和 Mermaid 图，后续再接原生多模态图片生成。

这样不会把“一小时写书”主流程变复杂。
