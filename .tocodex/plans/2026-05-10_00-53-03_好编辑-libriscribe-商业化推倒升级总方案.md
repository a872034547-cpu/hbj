# 好编辑 / Libriscribe 商业化推倒升级总方案

## 0. 总负责人判断

用户要求不是“小修小补”或 MVP，而是把当前本地 Streamlit 写作工具升级为可商用、可测试、可上线、可持续迭代的 AI 专著生产平台。因此实施原则是：

1. **不再围绕按钮堆功能**，改为围绕“项目—资料—大纲—流水线—审校—出版交付”的商业闭环重构。
2. **前端路由、后端服务、数据模型、任务系统、测试上线同步设计**，避免只改 UI 不改业务链路。
3. **保留现有可用能力作为迁移资产**，但把当前 Streamlit 单体定位为 2.0 过渡前端；核心业务逐步抽到服务层，便于未来迁移 FastAPI + Next.js。
4. **先做商业化架构与流程骨架，再分区替换旧逻辑**，避免一次性破坏现有章节生成、RAG、导出等已能工作的功能。

## 1. 现有项目关键发现

- [`app.py`](libriscribe/src/libriscribe/web/app.py:930) 已有单页路由、侧边导航、项目创建/加载、资料库、大纲、编辑器、聊天、设置、AI 配置。

- [`knowledge_base.py`](libriscribe/src/libriscribe/knowledge_base.py:34) 已有 `ChapterSection`，支持四级目录写作单元。
- [`knowledge_base.py`](libriscribe/src/libriscribe/knowledge_base.py:111) 已有 `SourceDocument`、`EvidenceChunk`、`Citation`、`TaskLog`、`BookReviewReport` 雏形。
- [`chapter_writer.py`](libriscribe/src/libriscribe/agents/chapter_writer.py:91) 已经从旧场景写作转向学术小节写作。
- [`retriever.py`](libriscribe/src/libriscribe/rag/retriever.py:36) 已有 ChromaDB 检索封装。

- [`requirements.txt`](libriscribe/requirements.txt:18) 已包含 RAG、LangGraph、Streamlit、DOCX/PDF 依赖。

### 1.2 当前不符合商用标准的问题

1. **前端路由仍是工具页集合**
   - 当前页面是 `Dashboard / Outline / Sources / Editor / Chat / Settings / AIConfig`。
   - 缺少商业产品应有的：项目驾驶舱、研究工作台、生产流水线、质量中心、出版中心、运营设置、审计日志。

2. **后端没有独立服务层**
   - 大量业务函数直接写在 [`app.py`](libriscribe/src/libriscribe/web/app.py:1)，超过 3000 行。
   - UI、文件读写、任务调度、LLM 调用、导出调用耦合严重。

3. **任务系统不可恢复**
   - 当前后台任务主要存在 `session_state`，浏览器会话和进程重启后不可恢复。
   - 商用级全书生成必须有任务日志、断点续跑、失败队列、重试策略、运行审计。

4. **RAG 与引用链还未真正闭环**
   - 已有 `SourceDocument / EvidenceChunk / Citation` 模型，但写作时并未稳定记录“正文论断—证据片段—引用编号—导出参考文献”。
   - 用户无法清楚看到每章资料覆盖、证据缺口、引用风险。

5. **测试体系缺失**
   - 搜索项目后没有发现 `pytest`、`unittest` 或测试用例。
   - 商用要求必须覆盖：大纲解析、RAG 索引、章节生成降级、导出、路由渲染、模型配置、任务恢复。

6. **UI 视觉有改进，但产品级信息架构不足**
   - 当前已有米白玻璃风 CSS，但页面结构仍偏 Streamlit 表单。
   - 需要参考顶级同类平台重做：统一工作台、左侧流程导航、顶部项目状态、卡片式任务、证据侧栏、质量评分、导出交付包。

## 2. 20+ 同类平台调研结论

本次调研覆盖已抓取页面和公开产品定位，分为学术写作、知识库研究、文献引用、企业 AI 工作流、文档协作、出版排版六类。

### 2.1 学术写作与引用类

1. **Jenni AI**
   - 核心：read / write / cite 一体化。
   - 借鉴：每个 claim 可追踪到 PDF 页码和段落；2600+ 引用样式；DOCX / LaTeX / HTML 导出。
   - 对本项目：必须建立“正文句子—证据片段—引用记录—导出参考文献”。

2. **Paperpal**
   - 核心：Research / Write / Cite / Plagiarism / AI Review / AI Detector。
   - 借鉴：导出前质量检查、投稿前体检、ISO/安全背书、插件生态。
   - 对本项目：新增“质量中心”和“出版前体检报告”。

3. **SciSpace / Typeset**
   - 核心：150+ research tools、280M papers、Chat PDF、Literature Review、Citation Generator、Extract Data。
   - 借鉴：工具矩阵 + 研究 Agent Gallery。
   - 对本项目：将“聊天页”升级为“研究工具箱 / Agent 中心”。

4. **Consensus**
   - 核心：从论文证据中回答研究问题。
   - 借鉴：基于论文共识和证据强度，而不是泛泛回答。
   - 对本项目：资料库回答必须显示证据支持度和资料不足提示。

5. **Elicit**
   - 核心：AI 文献综述、论文筛选、证据表格。
   - 借鉴：把资料转成结构化证据表。
   - 对本项目：增加“章节资料覆盖图”和“证据表”。

6. **Scholarcy**
   - 核心：论文摘要卡片、快速提炼贡献、方法、结果。
   - 借鉴：文档入库后自动生成摘要卡。
   - 对本项目：资料库每个文档生成摘要、关键词、适用章节。

7. **ResearchRabbit**
   - 核心：文献发现图谱。
   - 借鉴：相关资料网络和推荐路径。
   - 对本项目：后续增加“资料关系图谱”。

8. **Connected Papers**
   - 核心：论文关联网络。
   - 借鉴：从一篇关键文献扩展研究脉络。
   - 对本项目：资料库可增加“同主题资料推荐/缺口提示”。

### 2.2 文献管理与引用类

9. **Zotero**
   - 核心：收集、组织、标注、引用、共享。
   - 借鉴：集合、标签、Word/Google Docs 插件、9000+ 引用样式、开源和数据控制。
   - 对本项目：来源库要支持标签、集合、引用字段、导入导出。

10. **Mendeley**
   - 核心：reference manager + AI library assistant。
   - 借鉴：Ask my library、从个人资料库中回答、PDF 标注。
   - 对本项目：资料库页新增“问我的资料库”。

11. **EndNote**
   - 核心：专业参考文献管理、Cite While You Write、撤稿提醒、Web of Science 数据。
   - 借鉴：引用准确性、撤稿/风险提醒、组织版支持。
   - 对本项目：引用核验中心应有“缺 DOI / 缺页码 / 未核验 / 疑似幻觉”状态。

12. **ZoteroBib**
   - 核心：快速生成 bibliography。
   - 借鉴：轻量引用格式化入口。
   - 对本项目：导出中心提供独立“参考文献生成/格式化”。

### 2.3 知识库研究类

13. **NotebookLM**
   - 核心：资料优先的 AI Research Tool。
   - 借鉴：回答基于用户资料、来源展示、资料摘要、资料对话。
   - 对本项目：大纲生成前先做资料覆盖分析。

14. **Perplexity**
   - 核心：带来源的答案引擎。
   - 借鉴：答案必须显示来源、可追踪。
   - 对本项目：AI 生成内容不得无来源生成事实性引用。

   - 借鉴：Agent 可在文档空间中执行多步任务；管理员可控。
   - 对本项目：未来需要团队空间、权限、任务审计、模型使用统计。

### 2.4 企业 AI 工作流类

17. **Copy.ai**

   - 借鉴：治理、合规、团队风格规则。

   - 借鉴：工具箱矩阵入口清晰。

### 2.5 文档协作与出版排版类

21. **Overleaf**

## 3. 推荐的新产品定位

升级后定位为：

> **面向中文学术专著、教材、行业白皮书、政策研究和企业研究报告的 AI 专著生产平台。以用户资料为可信来源，以章节流水线为生产引擎，以引用核验和出版体检为商用可靠性保障。**

产品价值主张：

- **可控**：目录、字数、模型、术语、风格、提示词都可配置。
- **可信**：事实性内容尽量绑定证据；无资料则明确标记信息缺失。
- **可恢复**：长任务失败可续跑。
- **可审计**：每次生成、重试、审校、导出都有日志。
- **可出版**：DOCX / PDF / LaTeX / Markdown / 交付包稳定输出。

#### 资料库 / RAG 中心
- 上传 PDF / DOCX / TXT / HTML / Excel。
- 文档摘要、标签、适用章节。
- 切片数量、页码/段落、hash。
- 检索测试。
- 章节资料覆盖图。
- 证据收藏到章节/小节。

#### 大纲规划器
- AI 生成全书大纲。

- 全书生成任务。
- 单章生成任务。
- 缺失小节生成。

- 任务断点续跑。

#### 章节编辑器
- 左侧目录树。
- 中间正文编辑。
- 右侧证据/引用/术语/评审侧栏。

#### 引用与事实核验中心
- 全书引用列表。

#### 审校与质量中心

#### 提示词中心

## 12. 风险与控制

### 风险 1：一次性改 `app.py` 过大

控制：先新增服务层和组件，逐步替换页面函数，不直接删除旧函数。

### 风险 2：Streamlit 不适合长期商业化

控制：短期用 Streamlit 完成业务闭环；服务层按未来 FastAPI API 设计，后续可无痛迁移 Next.js。

### 风险 3：引用核验复杂

控制：第一步先做状态和证据绑定，不承诺自动判定所有事实；缺证据时明确标红。

### 风险 4：测试依赖环境复杂

控制：测试分层：纯函数测试优先，LLM 和 ChromaDB 用 mock 或跳过标记。

### 风险 5：旧小说概念污染专著产品

控制：保留 `Scene` 兼容，但 UI 主流程全部使用“章节/小节/资料/证据/引用/审校”。
